資料處理流程與隱私處理

本頁不是靜態示意——瀏覽器會讀取同目錄下的 parts-kpi-data.json（由 extract_dataset.py 從原始 Excel 匯出，約 900KB）， 在使用者裝置端即時完成本頁所有加總與比對。因為這個 repo 是公開的 GitHub repo，匯出時已做過隱私處理： 車牌號碼一律替換為不可逆的流水代號（V00001…），跨表 join／去重仍然正確，但不會外流真實車牌； 客戶姓名、電話、Email、地址、生日一律不匯出（本頁任何 KPI 都不需要這些欄位）；門市名稱、車型代碼、金額等非個資欄位維持原樣。 頁面本身也加了與「售服績效戰情中心」相同機制的密碼鎖（前端 SHA-256 驗證）。

以下對照表整理報表中 13 張工作表的角色分工，供未來要接 Power BI／Tableau 或擴充月份時參考。每張表在匯出時已預先套用固定篩選條件（見表頭第 2–9 列），建模時建議先剝除表頭區塊，僅載入實際欄位標題列以下的明細資料。

Calculation Logic · 對應的 DAX / SQL 寫法

四大核心指標計算邏輯

本頁的 JavaScript 運算引擎與下面的 DAX 邏輯一一對應（可對照 parts-kpi-data.json 旁的原始碼檢視）。若未來要遷移到 Power BI／Tableau，可直接沿用以下寫法；差異只在於本頁用 JS 物件模擬星型схема，正式 BI 工具則用真正的資料模型關聯。

① NVS 單台產值目標 190 元/台
-- Step 1（Power Query / SQL View）：在 NVS明細 建立「還原金額」欄
還原金額 =
  IF([價別] IN {"特價","理賠價","售價"}, [金額],
     IF([價別] IN {"加價購","零件換購"},
        LOOKUPVALUE(加價購轉回表[金額], 加價購轉回表[件號], [項目]),
        BLANK()))

-- Step 2（DAX 量值）
NVS分子 := SUMX(NVS明細, [還原金額]) / 1.05

NVS分母 :=
  CALCULATE(
      DISTINCTCOUNT(定保台數[牌照號碼]),
      定保台數[品牌] = "NISSAN"
  )

NVS單台產值 := DIVIDE([NVS分子], [NVS分母])
注意：「金額」欄在 NVS明細／六大銷售明細中重複出現兩次（原始金額 vs 獎金金額），匯入時務必重新命名以免加總到錯誤欄位——這是本檔案最容易踩雷的地方。本頁的擷取腳本已正確只取第一個「金額」欄。
② S 餐使用率目標 96%
-- Step 1（ETL）：定保台數 建立車輛屬性旗標
是否S餐對象車型 = LEFT(車型代碼,3) IN {"B18","P15","C12","T32","T33"}
是否排除_電動車 = LEFT(牌照號碼,1) = "E"

-- 車輛類別判定：完整還原「條件說明」工作表原始 IF 公式（軍車/租賃車/計程車三段式判斷）
車輛類別判定 =
  VAR P = 牌照號碼
  VAR L = LEN(P)
  VAR DashPos = IFERROR(SEARCH("-", P), -1)
  RETURN
    IF(LEFT(P,1) = "軍", "軍車",
    IF(AND(L=6, DashPos=-1), "租賃車",
    IF(OR(
         AND(L=8, DashPos=4, LEFT(P,1)="R"),
         AND(DashPos=3, LEFT(P,1)=MID(P,2,1)),
         AND(DashPos=5, RIGHT(P,1)=MID(P,6,1))
       ), "租賃車",
    IF(AND(L=6, OR(DashPos=3, DashPos=4)), "計程車", "一般車"))))

是否排除_軍車   = 車輛類別判定 = "軍車"
是否排除_租賃車 = 車輛類別判定 = "租賃車"
是否排除_公司車 = 車輛類別判定 = "一般車" AND LEN(車主) > 4
是否排除_T33專案 = 車型代碼 LIKE "T33%"
                    AND 牌照號碼 IN (SELECT regono FROM L34_T33專案車型)

-- Step 2（ETL）：C12/T32 資格比對（僅此二車系需要）
是否C12T32合格 =
  車型代碼&規格&選配碼  -- 比對c12t32對象車型規格選配.合併
  IN (SELECT 合併 FROM c12t32對象車型規格選配)
  -- B18 / P15 / T33 車型不受此限制，視為天然合格

-- Step 3（ETL）：是否使用S餐（比對油品銷售明細）
是否使用S餐 =
  牌照號碼 IN (
    SELECT 牌照號碼 FROM 油品銷售明細
    WHERE 項目 IN ("101210W30S23","101225W30S23","101220W20123",
                   "101210W20C23","101220530123")
  )

-- Step 4（DAX 量值，讀取上面已算好的旗標欄）
S餐分母 := CALCULATE(DISTINCTCOUNT(定保台數[牌照號碼]),
             定保台數[是否S餐對象車型] = TRUE,
             定保台數[是否排除_電動車] = FALSE,
             定保台數[是否排除_軍車]   = FALSE,
             定保台數[是否排除_租賃車] = FALSE,
             定保台數[是否排除_公司車] = FALSE,
             定保台數[是否排除_T33專案] = FALSE,
             OR(定保台數[是否C12T32合格]=TRUE, NOT(LEFT(車型代碼,3) IN {"C12","T32"})))

S餐分子 := CALCULATE([S餐分母的同一組車輛], 定保台數[是否使用S餐] = TRUE)
S餐使用率 := DIVIDE([S餐分子], [S餐分母])
這是四個指標中邏輯最深的一個，牽涉 3 張排除/白名單表。本頁初版設計時曾用簡化邏輯粗估為 72.7%，套用完整的 C12/T32 白名單比對與 T33 專案排除後，實際結果是 96.2%——兩者差了 23.5 個百分點，證明這一步驟不能省略（見下方策略提醒 #1）。
③ 輪胎更換率目標 10.8%
輪胎分母車輛 :=
  FILTER(輪胎電瓶有費台數,
      輪胎電瓶有費台數[工單類別] = "自費" &&
      OR(輪胎電瓶有費台數[車齡 (年)] > 4,
         輪胎電瓶有費台數[本次進廠里程] > 40000))

輪胎分母 := DISTINCTCOUNT(輪胎分母車輛[牌照號碼])

輪胎分子 :=
  CALCULATE(
      DISTINCTCOUNT(輪胎電瓶銷售明細[牌照號碼]),
      輪胎電瓶銷售明細[工單類別] = "自費",
      輪胎電瓶銷售明細[零件分類] = "輪胎",
      FILTER(輪胎電瓶銷售明細, [數量] - [退庫] > 0),
      輪胎電瓶銷售明細[牌照號碼] IN VALUES(輪胎分母車輛[牌照號碼])  -- 分子必須也在分母名單內
  )

輪胎更換率 := DIVIDE([輪胎分子], [輪胎分母])
⚠ 兩處待確認事項：(1) 兩張來源表在本次匯出的「期間」篩選不同步（銷售明細僅到 8/15，有費台數到 8/31），本頁沿用同一批匯出檔，這個落差目前仍然存在，正式排程請務必讓兩張表共用同一個日期參數重新匯出。(2) 「條件說明」原始公式字面上只寫「銷售明細台數 ÷ 對象台數」，沒有明講分子是否要落在分母名單內；本頁選擇要求交集（如上），原因是實測發現不交集時、按車型拆開會出現超過 100% 的更換率（T33 電瓶一度算出 755%），交集後所有比率才會落在合理的 0–100% 區間。上線前務必請公式擁有者確認這個判讀是否符合原意。
④ 電瓶更換率目標 14.8%
電瓶分母車輛 :=
  FILTER(輪胎電瓶有費台數,
      輪胎電瓶有費台數[工單類別] = "自費" &&
      OR(輪胎電瓶有費台數[車齡 (年)] > 2,
         輪胎電瓶有費台數[本次進廠里程] > 20000))

電瓶分母 := DISTINCTCOUNT(電瓶分母車輛[牌照號碼])

電瓶分子 :=
  CALCULATE(
      DISTINCTCOUNT(輪胎電瓶銷售明細[牌照號碼]),
      輪胎電瓶銷售明細[工單類別] = "自費",
      輪胎電瓶銷售明細[零件分類] = "電瓶",
      FILTER(輪胎電瓶銷售明細, [數量] - [退庫] > 0),
      輪胎電瓶銷售明細[牌照號碼] IN VALUES(電瓶分母車輛[牌照號碼])
  )
電瓶更換率 := DIVIDE([電瓶分子], [電瓶分母])
與輪胎共用同一張分母來源表，車齡/里程門檻不同（2年/20,000km vs 4年/40,000km）——建議做成參數表（Threshold Table）驅動，而非寫死兩份幾乎相同的量值。「分子必須交集分母」的判讀理由同輪胎，見左方註記。
⑤ 六大商品營收與毛利達成率9 品項 × 月目標
-- Step 1（ETL）：六大銷售明細(零件)/(工資) 的「說明」為自由文字品名，
--            需先建立「品項分類對照表」(關鍵字 → 標準品項)
品項分類對照:
  說明 LIKE "%劃線碟%"            → 劃線碟
  說明 LIKE "%椿頭%" / "%樁頭%"   → 電瓶樁頭
  說明 LIKE "%冷煤強化劑%"         → 冷煤強化劑
  說明 LIKE "%冷氣系統%"           → 冷氣系統養護
  說明 LIKE "%鈦晶%內裝%"          → 鈦晶內裝
  說明 LIKE "%鈦晶%外觀%"          → 鈦晶外觀
  說明 LIKE "%空力雨刷%"           → 空力雨刷
  說明 LIKE "%電動窗%"             → 電動窗養護
  說明 LIKE "%卡鉗%潤滑%" / "%滑銷%" → 碟式煞車潤滑

-- Step 2（DAX 量值）
品項實際營收 := SUM(六大銷售明細零件[金額]) + SUM(六大銷售明細工資[金額])
品項實際毛利 := [品項實際營收] - SUM(六大銷售明細零件[成本]) - SUM(六大銷售明細工資[成本])

品項月目標營收 := LOOKUPVALUE(六大各廠目標[營收目標(含工)], 六大各廠目標[品項], [品項]) / 12
品項月目標毛利 := LOOKUPVALUE(六大各廠目標[獲利目標(含工)], 六大各廠目標[品項], [品項]) / 12

達成率 := DIVIDE([品項實際營收], [品項月目標營收])
⚠ 兩個待確認事項：(1) 目標表原始欄位判讀為年度目標（單價×年度目標台數=含工營收目標，經反算驗證吻合），本頁除以 12 僅為近似月目標，正式邏輯建議向目標表擁有者確認是否已有月度拆分版本。(2) 新北／台北兩區塊目標數字完全相同，本頁先取單一區塊值處理，未加總——這會讓目標值差 2 倍，務必先確認語意再上線。

Strategic Notes · 分析與策略提醒

上線前後務必留意的事

✓
套用完整比對邏輯後，S 餐使用率其實已達標 初版設計稿用簡化邏輯粗估 S 餐使用率僅 72.7%（遠低於 96% 目標），但那個估算完全沒套用 C12/T32 選配白名單與 T33 專案排除。套用完整邏輯後，真實結果是 96.2%（1,018/1,058 台），已達成目標。這也證明了為什麼不能用「看起來合理」的簡化公式做正式判讀。

輪胎/電瓶更換率公式字面上未要求「分子⊆分母」——不要求時會算出超過 100% 「條件說明」原始公式只寫「銷售明細台數 ÷ 對象台數」，沒有明講買家是否要落在達門檻名單內。實測按車型拆開驗證時發現：若不要求交集，T33 電瓶更換率會算出 755%（因為 T33 車齡普遍很輕，自費換電瓶的人大多還沒達到車齡 2 年門檻，分子population 與分母population 幾乎不重疊）。公司整體加總時因為分母夠大才「看起來合理」掩蓋了這個問題。本頁已改為要求分子必須交集分母，所有比率因此保證落在 0–100%；連帶地，卡片上的輪胎/電瓶更換率從原本的 15.0%／18.7%（達成 140%／127%）修正為 10.1%／14.5%（接近但未達目標 10.8%／14.8%）。上線前務必請公式擁有者確認這個判讀是否符合原意——這個判讀直接決定這兩個指標「有沒有達標」的結論相反。

輪胎 / 電瓶更換率的分子分母期間不同步（目前仍未修正） 「輪胎&電瓶銷售明細」（分子）本次匯出僅涵蓋 8/1–8/15，但「輪胎&電瓶有費台數」（分母）涵蓋整月 8/1–8/31。本頁沿用同一批匯出檔，數字可能仍偏高，卡片上已加註警示。正式排程前務必請 IT／DMS 廠商用同一組日期參數重新匯出這兩張表，這是上線前的必要條件，不是可以之後再修的小事。
