Calculation Logic · DAX / SQL 建議

四大核心指標計算邏輯

以下以 Power BI DAX 為主要示例（Tableau／SQL 邏輯相同，差異僅在語法），並標註哪些步驟建議在 資料前處理層（Power Query / dbt / SQL View） 完成，而非直接寫在量值中——因為本案有多張「橋接表 / 白名單 / 排除清單」，用 DAX 逐列比對效能較差，先在 ETL 建好旗標欄位再彙總會乾淨很多。

① NVS 單台產值目標 190 元/台
-- Step 1（Power Query / SQL View）：在 NVS明細 建立「還原金額」欄
還原金額 =
  IF([價別] IN {"特價","理賠價","售價"}, [金額],
     IF([價別] IN {"加價購","零件換購"},
        LOOKUPVALUE(加價購轉回表[金額], 加價購轉回表[件號], [項目]),
        BLANK()))

-- Step 2（DAX 量值）
NVS分子 := SUMX(NVS明細, [還原金額]) / 1.05

NVS分母 :=
  CALCULATE(
      DISTINCTCOUNT(定保台數[牌照號碼]),
      定保台數[品牌] = "NISSAN"
  )

NVS單台產值 := DIVIDE([NVS分子], [NVS分母])
注意：「金額」欄在 NVS明細／六大銷售明細中重複出現兩次（原始金額 vs 獎金金額），匯入時務必重新命名以免加總到錯誤欄位——這是本檔案最容易踩雷的地方。
② S 餐使用率目標 96%
-- Step 1（ETL）：定保台數 建立車輛屬性旗標
是否S餐對象車型 = LEFT(車型代碼,3) IN {"B18","P15","C12","T32","T33"}
是否排除_電動車 = LEFT(牌照號碼,1) = "E"

-- 車輛類別判定：完整還原「條件說明」工作表原始 IF 公式（軍車/租賃車/計程車三段式判斷）
車輛類別判定 =
  VAR P = 牌照號碼
  VAR L = LEN(P)
  VAR DashPos = IFERROR(SEARCH("-", P), -1)
  RETURN
    IF(LEFT(P,1) = "軍", "軍車",
    IF(AND(L=6, DashPos=-1), "租賃車",
    IF(OR(
         AND(L=8, DashPos=4, LEFT(P,1)="R"),
         AND(DashPos=3, LEFT(P,1)=MID(P,2,1)),
         AND(DashPos=5, RIGHT(P,1)=MID(P,6,1))
       ), "租賃車",
    IF(AND(L=6, OR(DashPos=3, DashPos=4)), "計程車", "一般車"))))

是否排除_軍車   = 車輛類別判定 = "軍車"
是否排除_租賃車 = 車輛類別判定 = "租賃車"
是否排除_公司車 = 車輛類別判定 = "一般車" AND LEN(車主) > 4
是否排除_T33專案 = 車型代碼 LIKE "T33%"
                    AND 牌照號碼 IN (SELECT regono FROM L34_T33專案車型)

-- Step 2（ETL）：C12/T32 資格比對（僅此二車系需要）
是否C12T32合格 =
  車型代碼&規格&選配碼  -- 比對c12t32對象車型規格選配.合併
  IN (SELECT 合併 FROM c12t32對象車型規格選配)
  -- B18 / P15 / T33 車型不受此限制，視為天然合格

-- Step 3（ETL）：是否使用S餐（比對油品銷售明細）
是否使用S餐 =
  牌照號碼 IN (
    SELECT 牌照號碼 FROM 油品銷售明細
    WHERE 項目 IN ("101210W30S23","101225W30S23","101220W20123",
                   "101210W20C23","101220530123")
  )

-- Step 4（DAX 量值，讀取上面已算好的旗標欄）
S餐分母 := CALCULATE(DISTINCTCOUNT(定保台數[牌照號碼]),
             定保台數[是否S餐對象車型] = TRUE,
             定保台數[是否排除_電動車] = FALSE,
             定保台數[是否排除_軍車]   = FALSE,
             定保台數[是否排除_租賃車] = FALSE,
             定保台數[是否排除_公司車] = FALSE,
             定保台數[是否排除_T33專案] = FALSE,
             OR(定保台數[是否C12T32合格]=TRUE, NOT(LEFT(車型代碼,3) IN {"C12","T32"})))

S餐分子 := CALCULATE([S餐分母的同一組車輛], 定保台數[是否使用S餐] = TRUE)
S餐使用率 := DIVIDE([S餐分子], [S餐分母])
這是四個指標中邏輯最深的一個：牽涉 3 張排除/白名單表。強烈建議在 SQL View 或 Power Query 把「是否使用S餐」「是否合格」都算成 0/1 旗標欄後再匯入模型，量值只做 CALCULATE 加總——維護與除錯都容易得多。
③ 輪胎更換率目標 10.8%
輪胎分子 :=
  CALCULATE(
      DISTINCTCOUNT(輪胎電瓶銷售明細[牌照號碼]),
      輪胎電瓶銷售明細[工單類別] = "自費",
      輪胎電瓶銷售明細[零件分類] = "輪胎",
      FILTER(輪胎電瓶銷售明細, [數量] - [退庫] > 0)
  )

輪胎分母 :=
  CALCULATE(
      DISTINCTCOUNT(輪胎電瓶有費台數[牌照號碼]),
      輪胎電瓶有費台數[工單類別] = "自費",
      OR(輪胎電瓶有費台數[車齡 (年)] > 4,
         輪胎電瓶有費台數[本次進廠里程] > 40000)
  )

輪胎更換率 := DIVIDE([輪胎分子], [輪胎分母])
⚠ 兩張來源表在本次匯出的「期間」篩選不同步（銷售明細僅到 8/15，有費台數到 8/31）。正式建模時務必在資料源設定同一個期間參數，兩張表都用同一組日期界線，否則分子/分母時間窗不一致會系統性高估或低估更換率。
④ 電瓶更換率目標 14.8%
電瓶分子 :=

      輪胎電瓶銷售明細[工單類別] = "自費",

  )
電瓶更換率 := DIVIDE([電瓶分子], [電瓶分母])

⑤ 六大商品營收與毛利達成率9 品項 × 月目標
-- Step 1（ETL）：六大銷售明細(零件)/(工資) 的「說明」為自由文字品名，
--            需先建立「品項分類對照表」(關鍵字 → 標準品項)
品項分類對照:
  說明 LIKE "%劃線碟%"            → 劃線碟
  說明 LIKE "%椿頭%" / "%樁頭%"   → 電瓶樁頭
  說明 LIKE "%冷煤強化劑%"         → 冷煤強化劑
  說明 LIKE "%冷氣系統%"           → 冷氣系統養護
  說明 LIKE "%鈦晶%內裝%"          → 鈦晶內裝
  說明 LIKE "%鈦晶%外觀%"          → 鈦晶外觀
  說明 LIKE "%空力雨刷%"           → 空力雨刷
  說明 LIKE "%電動窗%"             → 電動窗養護
  說明 LIKE "%卡鉗%潤滑%" / "%滑銷%" → 碟式煞車潤滑

-- Step 2（DAX 量值）
品項實際營收 := SUM(六大銷售明細零件[金額]) + SUM(六大銷售明細工資[金額])
品項實際毛利 := [品項實際營收] - SUM(六大銷售明細零件[成本]) - SUM(六大銷售明細工資[成本])

品項月目標營收 := LOOKUPVALUE(六大各廠目標[營收目標(含工)], 六大各廠目標[品項], [品項]) / 12
品項月目標毛利 := LOOKUPVALUE(六大各廠目標[獲利目標(含工)], 六大各廠目標[品項], [品項]) / 12

達成率 := DIVIDE([品項實際營收], [品項月目標營收])
⚠ 兩個待確認事項：(1) 目標表原始欄位「銷售目標／營收目標」判讀為年度目標（單價×年度目標台數=含工營收目標，經反算驗證吻合），除以 12 僅為近似月目標，正式邏輯建議向目標表擁有者確認是否已有月度拆分版本。(2) 新北／台北兩區塊目標數字完全相同，需確認這是「兩區各自的目標」（加總=全公司目標）還是「範本重複顯示」——目前設計先以不加總、取單一區塊值處理。
Interactivity · 互動切換器建議

Slicers 設計

月份 / 期間
依「入帳日期」或「發票日期」建立日期表，支援月選擇 + 近12個月趨勢；務必統一各事實表的日期基準（發票日 vs 結帳日 vs 開單時間，本檔案三者混用）。
廠區 / 門市
依「服務廠」欄位（如輔大廠、三重廠…20 個廠區）建立門市維度表；六大各廠目標另有新北/台北兩個區域分組，需建立門市→區域對照表串接。
車型
車型代碼前綴分組（B18/P15/C12/T32/T33 = S餐對象；其餘為一般車型），並提供「品牌」二級篩選（目前資料全為 NISSAN，未來若納入 INFINITI 需保留擴充欄位）。
車輛類別
一般車 / 公司車 / 租賃車 / 軍車 / 電動車 五態切換器，預設鎖定「一般車」；開放使用者手動勾選以檢視排除對象的影響幅度。
工單類別
自費 / 理賠 / 保固 等，輪胎、電瓶、六大商品指標皆與此欄位強相關，建議做成頁面層級篩選而非單一視覺篩選。
品項 / 商品類別
六大商品 9 品項（見下方策略提醒）+ 零件分類（輪胎/電瓶/化學品/油品…），供矩陣圖鑽取單一品項的門市排行。
Strategic Notes · 分析與策略提醒

建置前務必確認的 8 件事

1
「六大商品」實為 9 個品項，非 6 個 六大各廠目標表列出劃線碟、電瓶樁頭、冷煤強化劑、冷氣系統養護、鈦晶內裝、鈦晶外觀、空力雨刷、電動窗養護、碟式煞車潤滑共 9 項。命名沿用歷史慣稱即可，但儀表板標題與矩陣圖標籤建議明確標示 9 品項，避免使用者誤以為漏了 3 項。
2
輪胎 / 電瓶更換率的分子分母期間不同步 本次匯出中「輪胎&電瓶銷售明細」僅涵蓋 8/1–8/15（半個月），但「輪胎&電瓶有費台數」（分母）涵蓋整月 8/1–8/31。直接相除會系統性高估更換率（本次試算輪胎 15.1%／電瓶 18.9% 明顯優於目標，需先排除此期間效應才能判斷是否真達標）。正式排程建議兩張表共用同一個日期參數表。
3
六大商品本期實際達成率普遍偏低，其中 2 品項掛零 以年度目標 ÷12 估算月目標後，9 品項整體達成率約 25%，其中「冷氣系統養護」與「鈦晶外觀」本期完全無銷售紀錄。建議先確認是否為品名關鍵字比對遺漏（自由文字品名容易漏配），若確認真無銷售，則是第一個要追的營運缺口。
4
六大各廠目標「新北」「台北」兩區塊數字完全相同 兩區的銷售目標、售價、成本、營收/獲利目標逐欄位比對完全一致，較不像是各自獨立的區域目標。建議與目標表維護者確認：究竟是「公司目標套用兩份範本」還是「兩區應加總才是全公司目標」，這會讓最終目標值差 2 倍，直接影響儀表板的達成率判讀。

「金額」欄位在多張表中重複出現，需重新命名 NVS明細、六大銷售明細(零件/工資)、油品銷售明細皆有兩個「金額」欄（第一個為銷售金額，第二個緊接在百分比%之後、實為獎金金額）。Power Query 載入時務必依欄位順序重新命名，避免量值誤加總到獎金欄。
